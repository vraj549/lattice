# Review findings — September 2026

Ten reviewers went through the codebase treating it as a prototype being turned
into a serious tool. This file is the backlog that came out of it.

**Only verified findings are listed.** Each one has a reproduction that was run,
or a source location that was read. Anything a reviewer asserted but did not
demonstrate is not here.

Status, as of the fix pass that followed:

| # | Finding | Status |
|---|---------|--------|
| 1 | Bolt at 170% of yield reported feasible | **fixed** — `passes` verdict, working-stress check |
| 2 | CalculiX writes the wrong analysis's BCs | **fixed** — `analysis_index()`, one derivation |
| 3 | Bolt end selection ignores bending | **fixed** — `worst_end()` ranks on combined stress |
| 4 | Derived-result caches never invalidated | **fixed** — stamped with the run's signature |
| 5 | Two version constants have drifted | **fixed** — `DECK_FORMAT` bumped; `MESH_FORMAT` served, not copied |
| 6 | One undo can wipe fourteen face picks | **fixed** — `recordEdit()`, and undo worked at all for the first time |
| 7 | Group identity is positional | partly — the wrong answers it caused (2, 3, and the sizing mis-join) are fixed; the `stats["groups"]` refactor is not |
| 8 | Mesh and solve not mutually exclusive | **fixed** — `owner_of_mesh()` |

Found during the fix pass and also fixed, none of which a reviewer had reached:

- **Nonlinear contact was absent from every dynamic deck.** A sliding or
  separating interface was dropped from modal, harmonic, random and shock
  rather than tied, which disconnects the parts instead of releasing them. The
  UI had been promising the opposite for months. Worst finding of the set.
- **Undo never recorded anything** made through `mutate()`. A guard that could
  only ever refuse, in code with no tests because it could not be imported.
- **A spectrum breakpoint at or below zero was dropped, not refused**, while
  the gate in front counted raw rows — a mistyped frequency reported g_RMS of
  zero, which reads as passing by an enormous margin.
- **A demo run was indistinguishable from a real one** once the session ended.
- **A typo in any enum was absorbed as a default** — unknown support type,
  load type, contact kind, and a mesh size of 0 all produced a finished run
  describing a different structure.
- **`LATTICE_ASTER_MODE=none` was ignored.**
- **Preload calibration reported unconverged runs as calibrated.**
- **Selecting a result left the previous analysis's field on screen.**

## Wrong answers

### 1. A bolt at 170% of yield is reported as feasible

`bolt_sizing.py` — `size_bolt()` computes the bending stress from the FE beam
moment into `sigma_red_B` and `utilisation`, and then `feasible` and `checks`
never look at either. They test only `F_Mmax <= F_Mzul`, head bearing pressure,
and fatigue.

```python
>>> size_bolt(d=10.0, pitch=1.5, l_K=20.0, F_A=500.0, F_Q=200.0, M_b=60000.0)
feasible      True
checks        []
sigma_red_B   1086 MPa      against R_p0.2 = 640 MPa
utilisation   1.70
```

This is the live path: `server.py:652` passes `M_b` straight from the beam's
`MFY`/`MFZ` on every call to the sizing endpoint. Any bracket, prying load or
eccentric joint reaches it. `M_b` appears **zero times** in
`tests/test_bolt_sizing.py`, so nothing would ever have caught it.

The tool's entire purpose is telling an engineer whether the bolt is good. This
says yes while the bolt yields.

**Fix:** gate `feasible` on `utilisation`, add the check text, return `sigma_b`
(the one intermediate the module does not return, in a module whose docstring
promises all of them), and test the bending path.

### 2. CalculiX writes the wrong analysis's boundary conditions

`ccx_writer.py` computes the analysis index correctly at line 439 and then
hardcodes `1` at lines 81, 103, 109, 117, 229, 252. `frictionless_nodes()` has
no `ai` parameter at all, so the bug is in the signature.

Mesh groups are named `SUP<analysis>_<item>`. For the **second or later
analysis in any project**:

- a frictionless symmetry constraint is written on analysis #1's node set — the
  model is constrained somewhere the engineer did not ask, then solved and
  reported;
- `support_frames` reads reactions at `SUP1_i`, so the equilibrium check either
  fires a false "do not use these results" on a correct run, or returns `[]` and
  is **silently skipped**.

That equilibrium check is the only defence against the documented
silent-multithreaded-SPOOLES failure, and CalculiX is the default engine on any
machine without code_aster.

**Fix:** thread `ai` through all six sites — but see finding 7, which makes the
class inexpressible.

### 3. Bolt end selection ignores bending

`results.py:510` and `shock.py:578` both keep the bolt end with the larger
`abs(N)`. An end with lower axial force but dominant bending is discarded, in
both the static sizing table and the shock combination. Same root as finding 1:
fixing the gate without fixing the selection still under-reports the worst case.

## The green tick can lie

### 4. Derived-result caches are never invalidated

`S.slipResults`, `S.shockResults`, `S.randomResults` are never deleted anywhere
in the codebase, and `openProject` does not reset them. Change an input, re-run:
the badge goes green and the panel still shows the previous run's numbers.

This defeats `solve_signature`, which exists precisely to stop it. The server
does its job; the client throws the answer away.

**Fix:** key derived results by the result's signature, so a stale entry cannot
be read. Reset in `openProject`.

### 5. Two version constants have drifted

- `ui.js` has `MESH_FORMAT = 2`; `meshing.py` has `3`, since v0.20.0. The UI
  guard therefore does not fire for exactly the meshes whose bolt beam spanned
  half the clamped length. The server's 422 contains it today.
- `DECK_FORMAT` was **not** bumped at v0.25.0, when shock combination changed
  from SRSS-everything to rigid-algebraic — a 21% non-conservative correction.
  Same setup JSON, different answer, identical hash. A v0.24 run reopened today
  is labelled current.
- `ccx_writer` has no format constant at all; ccx runs are fingerprinted with
  `comm_writer.DECK_FORMAT`.

The root: the signature versions the **deck**, but the engineering answer is
computed in Python at read time. The half that has actually changed and produced
wrong numbers is the half the signature cannot see.

**Fix:** one `FORMATS` dict covering every module that decides what a number
means, stored in `meta.json`, compared on read — so staleness says *which* thing
changed. Delete the JS copy and ask the server.

## Data loss

### 6. One undo can wipe fourteen face picks

Six sites mutate `setup` and call `scheduleSave()` instead of `mutate()`,
including **face picking** (`main.js:833`) and **bolt patterning**
(`main.js:883`) — the two most laborious actions in the application. Because
`baseline` is left stale, the *next* real `mutate()` snapshots from before the
bypass.

Pick 14 faces, change any field, press undo once: the field change and all 14
picks are gone.

**Fix:** route all six through `mutate`. The structural version is a `store.js`
that makes `setup` unreachable except through it, so a bypass throws.

## Structural

### 7. Group identity is positional across the mesh boundary

Groups are named by list position — `SUP{ai}_{i}`, `BOLT{i}`, `CTA{i}` — and
four modules reconstruct those names independently. A hardcoded index
type-checks. A reordered list silently re-points a constraint. This generates
findings 2 and 3, and also lets `server.bolt_sizing_table` mix a stable `id` key
with a mesh-time index, so deleting a bolt after solving sizes bolt B with bolt
A's forces.

The fix already exists in the codebase, applied to one of five group families:
`_add_remote_stubs` records `{"group": name, "id": item_id}`. Generalise it —
meshing writes `stats["groups"][item_id] = group_name`, everyone reads it, and
`group_name()` is deleted from three modules.

### 8. A mesh and a solve on one project are not mutually exclusive

`is_running` keys meshes on `pid` and solves on `pid/aid`, so re-meshing during
a solve is permitted. `_calibrate_preload` copies the shared `mesh/mesh.unv`
mid-solve, so a concurrent re-mesh gives a preload calibrated on one
discretisation and applied to another, at exit code 0.

## Product

Not defects. From the review of what a user needs rather than what the code does.

1. **There is no report.** No PDF, no HTML, no viewport capture — every panel
   terminates in CSV. An engineer cannot hand a colleague a result or put one in
   a design review, which caps the tool at a personal scratchpad regardless of
   how good the physics is. It is also the only place the verification work
   (equilibrium residual, truncation %, slip fractions, the stated limits in
   METHODS.md) becomes visible to anyone who did not run the job.
2. **Install is a build.** Upgrade pip first or the editable install fails while
   appearing to succeed; 400 MB of gmsh; then a tarball from a forum post and
   `wsl --import`. The macOS path reaches CalculiX, which cannot run bolts,
   harmonic, random or shock — that is, cannot run the product.
3. **Metric only.** "inch" appears in the codebase solely as a thread series.
4. **No margin of safety.** Everything needed to form `MS = σ_allow/(FS·σ) − 1`
   is computed and the number is never formed.
5. **No load-case combination.** Qualification is never one case; METHODS.md
   says to combine outside the tool, which means a spreadsheet.
6. **No shell elements.** Sheet-metal brackets are most of what this tool's user
   bolts together.
7. **No published V&V.** Two benchmarks exist, inside a test file.

## Freeze rather than extend

- **CalculiX parity.** It cannot run bolts, ties, harmonic, random or shock. It
  has already broken the code_aster path once via a shared-session option leak.
  Keep it as a quick-check engine; stop buying parity.
- **Hexahedra.** The geometry-rebuild-and-tag-rematch layer is load-bearing
  forever in a codebase whose recurring failure is silent identity mismatch.
  Never default, never extend.
